P1. User Confirmation. An impostor may impersonate a trusted person and attempt to transfer funds without proper authorization. Therefore, every transfer must have explicit user confirmation for the exact recipient and amount. A confirmation must be associated with the specific transfer request. Instructions contained in external messages, including SMS messages, must not be treated as user confirmation. 

P2. Additional Verification for Suspicious Recipients. A scammer often provides unfamiliar payment details and creates a sense of urgency to pressure the victim into transferring money. So, Transfers to unregistered recipients or recipients whose payment details originate from untrusted messages must not be executed without additional identity verification and a cooling-off period. A user's request to proceed does not, by itself, bypass these requirements.

P3. Daily Transfer Limit. A daily transfer limit can reduce potential financial losses if a user or an agent is deceived into making payments. The Payments Agent must not execute a transfer if the transfer amount, combined with the total amount transferred that day, exceeds the configured daily limit of $1,000. Transfers within the limit remain subject to all other applicable authorization requirements.

P4. Payment Information Provenance. Without tracking, information introduced by a scammer may be treated as real user-provided payment instructions. The system must track whether payment details originate from registered banking records, direct user input, or untrusted external messages. Rephrasing or repeating information from an untrusted message must not automatically change its recorded origin to trusted user input.

P5. Separation of Agent Responsibilities. Separating responsibilities prevents an agent that processes untrusted messages from directly controlling financial transactions. Only the Payments Agent may invoke the transfer execution tool. The Assistant Agent may request payment verification but must not directly execute transfers or modify banking records. The verification should not result in a transfer execution.

P6. Information Isolation Between Agents. Restricting information flow reduces unnecessary exposure of sensitive data and prevents malicious instructions embedded in external messages from crossing agent boundaries. The Assistant Agent must not access account balances or full bank account numbers directly. The Payments Agent must not receive the same message from the Assistant Agent, e.g., raw SMS content or unrelated conversation history. Communication between agents must be limited to the information necessary to verify and process the specific payment request.
